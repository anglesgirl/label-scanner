# LabelScanner v2 设计（重新设计）

> 依据：2026-09-11 用户提供的**真实标签照片**（6 类）+ 公司库存导入模板。

## 一、需求收敛：只有 3 个关键字段

| # | 字段 | 模板列 | 规则 |
|---|---|---|---|
| 1 | **物料编码** | **D** (DATA03) | 10 位 → 补 `01`；12 位 → 原样 |
| 2 | **序列号（箱号）** | **E** (DATA04) + **O** (DATA14) | 有 SN 填 SN；只有箱号则两列都填箱号 |
| 3 | **生产日期** | **I** (DATA08) | 归一成 `yyyymmdd` |

其余列留空，**F 数量**：有 SN 时 `1`，只有箱号时 `= QTY`。

## 二、三种采集场景（来自真实标签）

| 场景 | 真实样本 | 一箱出几条 | F |
|---|---|---|---|
| **打印机**（一箱一台） | 本体 `CV7DV0007F`+`3011231031`+`20250902`<br>A3 `ACP5P81000050`+`303020000401`+`2020/09/02`<br>A4 `CL7LV015J0`+`3010110050`+`2026-06-01` | **1 条** | 1 |
| **粉盒·有 SN（集成码）** | 二维码内 N 个 `SCAG2529704Bx`（`,` 分隔）<br>独立条码 = 箱号 `CA70450P10052278` | **N 条**（每 SN 一条，E 列同箱号） | 1 |
| **粉盒·只有箱号** | 只有箱号、无 SN | **1 条** | **= QTY** |

## 三、原项目的致命 bug（已定位到代码）

`BoxParser.kt` 的判定：
```kotlin
val isSnPrefix = material.isNotEmpty() && c.startsWith(material)
if (isSnPrefix)  → SN
else             → 第一个独立码当【箱号】，其余当 SN
```

**它假设「SN 以物料编码开头」——而真实标签全部不成立**：

| 物料编码 | 真实 SN | 以物料开头？ |
|---|---|---|
| `201121001601` | `SCAG2529704B3` | ❌ |
| `303020000401` | `ACP5P81000050` | ❌ |
| `3011231031` | `CV7DV0007F` | ❌ |

**后果（粉盒整箱为例）**：
- 第一个 SN `SCAG2529704B3` 被判成**箱号** ❌
- 真正的箱号 `CA70450P10052278` **无处可去、被丢弃** ❌
- SN **少 1 个**（8 → 7）❌
- **数据看起来完整，错得极难发现** ← 这正是"核对比重采还累"的根源

## 四、v2 识别规则（改用格式特征，不猜）

按**值的形态**分流，**不依赖"SN 是否以物料开头"**：

| 形态 | 判定 |
|---|---|
| 8 位数字 / 带分隔符（`- . /` 空格 `_`）/ 中文年月日 | **生产日期** → 归一 `yyyymmdd` |
| 13 位且 `69` 开头 | **EAN13** → 不填模板（系统版剔除） |
| 10 位纯数字 | **物料编码** → 补 `01` |
| 12 位纯数字 | **物料编码** → 原样 |
| `CA` / `PA` / `CL` 前缀的独立码 | **箱号** |
| **二维码**内容（`,` `;` 换行分隔） | **全部拆成 SN** |
| 其余字母数字混合码（6–30 位） | **SN** |

**两条去错规则**（新增，专治误判）：
- **前缀抑制**：短码是长码前缀 → **丢弃短的**（`ACP5P81` vs `ACP5P81000050`，前者是产品代码）
- **同值去重**：完全相同的值只保留一条（A3 标签上 SN 与 "Factory Original #" 同值）

## 五、采集时校验（治"事后核对"）

| 校验 | 当场行为 |
|---|---|
| **数量对账** | 标签 QTY=8、实扫 6 → 界面**持续显示"还差 2 个"**，不静默通过 |
| **SN 重复** | 同箱同 SN 再扫 → 标"重复，已忽略" |
| **物料格式** | 非 10/12 位 → 红字提示，不落库 |
| **日期归一** | `2026-06-01` / `2025.10.24` / `20250902` → 一律 `20260601` 形态 |
| **缺少关键字段** | 物料或日期缺失 → 明确提示缺哪项，允许手工补 |

原则：**宁可当场拦住让人重扫，也不产生"看起来对"的错数据**。

## 六、界面：一个入口走完全程

原项目 **5 个入口**（单条/单箱/拆分/托盘/设置）→ **v2 只有 1 个采集页**，扫什么自动认。

```
           📷 对准标签（进 App 直接开相机）
────────────────────────────────────────────
物料    201121001601              ✓
序列号  SCAG2529704B3 …（8 个）    ✓ 与 QTY 一致
日期    20251024                  ✓
箱号    CA70450P10052278          ✓
────────────────────────────────────────────
        [ 确认入库 ]  [ 重扫 ]  [ 手工补 ]
────────────────────────────────────────────
本托盘：3 箱 / 24 个 SN        [ 导出 WMS ]
```

- **实时显示抓到了什么** → 抓错当场重来，不留到事后
- **识别中区分度**：扫码（条码/二维码）为主，OCR 仅补齐 SAP 行 / 日期 / QTY
- **扫完一箱 → 「下一箱」**；**一托盘扫完 → 一次导出**

## 两种采集模式（务必区分，勿再混淆）

用户明确区分了两个不同诉求的采集场景。**早期版本把二者混在一起，
导致采集入库被做成了实时连续识别（费电、且不符合实际操作节奏）。**

### 模式 A：采集入库（当前唯一实现）

- **场景**：对着纸箱逐箱采集，一托盘一次
- **节奏**：**一箱一张**
  `进入托盘 → 对准标签 → 拍照 → 核对数据 → 对则保存 / 不对则重拍 → 下一张`
- **需要**：物料编码、序列号（箱号）、生产日期 —— **完整字段**
- **因此需要**：静图 + 透视矫正（出正图）+ OCR（部分字段只有印字，条码里没有）
- **省电要点**：只在按下快门那一刻采集；**核对期间暂停分析器**
- **不做**：实时连续识别、多帧累加（会产生"何时算完"的困惑与跨帧错值）

### 模式 B：卡板清单 / 大批量取码（**以后再做**）

- **场景**：快速清点，成批把条码读出来
- **节奏**：**实时连续扫**
- **需要**：**只要条码值**，**不需要 OCR**，不做字段核对
- **实现预留**：`camera/v2/SmartTrackAnalyzer.kt`、`camera/v2/LabelAnalyzerV2.kt`
  即为该模式准备（连续读码 + 去重），当前采集流程**不使用**它们。
  `SmartTrackAnalyzer` 里的变焦死区/限速逻辑可直接复用，但需注意
  它当初的震荡问题是"用并集算面积"导致的，已改为"最大单码框"。

### 判定规则（写代码前先问）

| 问题 | 模式 A | 模式 B |
|---|---|---|
| 要不要物料/日期等印字字段？ | 要 → 必须 OCR | 不要 |
| 要不要核对每一箱？ | 要 → 单张 + 暂停 | 不要 → 连续 |
| 相机要不要一直开？ | 不要（省电） | 要 |
